# E5 原生运行时与启动优化部署验证

2026-10-23。用户要求部署此前的 E5 移植。代码范围见
[共享运行时移植报告](E5-NATIVE-BACKPORT-20261023.zh-CN.md)。

## 目标与部署

核对此前维护过的同一台 E5：SSH 主机公钥、eMMC 身份、`device-profile=e5`、
设备树及现有独立内置根分区均匹配。维护连接绑定 USB 网卡的本地地址，未修改电脑
网卡、路由或无线连接。实际 DT 为 `sprd,ums512-base` / `sprd,ums9621`，充电芯片
驱动为 `aw32257-charger`。当前上网卡为 SIM2。

- 使用登记的 E5 源码视图与对象缓存，通过正式任务入口增量编译新内核及完整模块。
  内核从 `6.18.54-e5-mobile4 #7` 更新为 **#8**，共 **268 个配套模块**。
  [构建、模块完整性及硬件修复回归日志](../out/build-logs/20261023-072508-e5-native-live-kernel-50619/command.log)。
- 新内核与模块整套部署，没有因 release 字符串相同而只拷入新模块。
- 部署 **27 个运行文件**：静态 C AT 所有者、原生 RPC 与共享界面、只读 MM 镜像、
  充电/USB 事件实现、后台 CPU 选择和对应启动入口。依赖包均已存在，原 APN、
  热点及工程解析依赖与当前源码哈希一致，没有切换备用实现。
- Linux 为 B、Android 为 A；通过现有 OTA boot API 保留本机 boot 参数、槽位、
  设备 ramdisk、OTA 恢复钩子与诊断区域，仅替换 Linux 内核、配套启动模块和通用 init。
  Linux boot 写入后逐块回读验证，Android boot 前后 SHA-256 一致。
- 正常重启一次。没有格式化、缩扩容、改 GPT、写 NV/校准分区或改变默认启动系统。

## 实测结果

电脑侧维护证据位于 `work/e5-native-live/`，包括逐文件部署清单、模块清单、
`verification.json`、工程信息刷新结果和经过筛选的运行日志。没有导出短信正文、
SIM 标识、密码或通话内容作为验证日志。

| 项目 | 实际结果 |
| --- | --- |
| 新启动产物 | 重启 ID 已改变，运行 #8；Linux boot 签名及全部 268 个模块哈希通过，Android A 未变 |
| C AT 所有者 | nr2/nr6/nr7 均为新静态程序，实际通过各自持久 owner 完成 `CFUN?`；没有直接打开 MM 所有的通道 |
| 后台调度 | 三个 AT 所有者使用本机实际小核 `0-5`；MM、屏幕和音频不在本次限制范围 |
| 常驻服务 | MM 镜像、USB 守护、网络恢复、短信通知均运行 |
| D-Bus 镜像 | 识别实际 `unisoc-sipc` / `unisoc` 模组；当前 boot/PID 有效，状态文件权限 0600 |
| 看板与速率 | `e5status` 的 sysinfo/status/cells/rates/sms_head 实际调用通过；5 次系统信息调用的 SSH 往返约 93–110 ms，包含传输和进程调用开销 |
| 工程信息 | 实际启动原采集器，经新 C owner 取得数据；主用 SIM2 的小区及信号缓存刷新到 age=0，没有返回错误 |
| 蜂窝 | 原 SIM2 已恢复数据连接；没有切卡、强制重置射频或改 APN |
| 热点 | AP 已启动，信道 149、80 MHz；本轮没有另用手机验证热点上网 |
| 充电策略 | 保留原 `enabled=0`、停止 80/恢复 70 配置；新 status 查询正常。原服务未启用，本轮没有为了测试而开启阈值控制 |
| 用户设置 | `/etc/config`、shadow、SIM RF 及转发配置共 24 份已有文件哈希不变；默认 Linux 启动保留 |
| 机型专用中断模块 | UMS9620 LP_INTC 模块在本机 UMS9621 上按保护规则保持未加载，不把其他 SoC 的 MMIO 设置套入本机 |

首次重连检查时，MM 尚无已发布模组，镜像正确报告未就绪；随后经过端口探测、
模组启用与注册，SIM2 自行联网，未通过重启服务或重置射频绕过等待。
在 uptime **132.86 秒**的检查时 WAN 已连接，这是验证时刻，不是首次联网耗时。
本轮未做相同条件的冷启动前后对比，也没有验证长期待机功耗，不能据此宣称具体提速或省电幅度。
