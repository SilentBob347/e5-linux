# E5 启动、AT 与公共屏幕修复

## 已确认的问题与修改

- 维护部署直接复制 SIPC 加载模板，遗漏原来由后处理补入的发送参数和即时端口通知，导致回到驱动默认 300 ms，并等待全局 hotplug 队列。原始模板现在也带即时通知及显式发送参数。曾出现一轮模板注释引号错误导致服务未启动，已纠正并重新通过 shell 语法及实际启动验证。
- NV 准备在同一次调用中重复校验同一对工作副本。只复用本次调用已经完成且没有被导入覆盖的检查结果；下次启动重新完整检查。全文件比较覆盖头部、填充和尾部。物理 NV 的只读保护、来源哈希、复制完整性校验和使用中的 loop 拒绝规则保留。
- 按维护要求将 SIPC/MM 与独立 AT owner 的正常发送间隔改为 50 ms。共享更新钩子可将已有 100/300 ms 参数迁移到 50 ms。该值是当前策略，并非协议规定或已证明的硬件最小值。超时恢复、同步探测、原有 AT 持有者与命令顺序保留。
- 控制台的 1/2/3/4 提示来自标准 preinit 恢复窗口，不要求用户选完才启动。将窗口从 4 秒缩短为 1 秒，保留键盘、按钮、内核参数恢复入口；公共镜像和更新钩子都安装配置。
- AT 终端取消前端 RPC 合批等待。网页耗时仍包含网络、RPC、脚本和排队时间，不能等同于基带执行耗时。
- 公共屏幕不再横移整条多页绘制表面。各页保留 DOM/iframe 状态，以两个视口大小的图层并排滑动 240 ms，使用原来的缓动曲线，新旧内容不做透明叠加。快速连续切页会清理旧过渡，关闭动画和减少动态效果设置有效。

## 实机结果

对象是通过原有 SSH 主机密钥及存储身份核对的 E5，当前使用 SIM2；同一固件和用户配置。没有写入启动分区、分区表或原始 NV，也没有为提速重置射频、禁用睡眠或删减通话/短信功能。

| 项目 | 结果 |
| --- | --- |
| 回归部署最初的端口发现 | WWAN 出现约 30.8 秒，MM 约 71 秒才收到端口 |
| 恢复即时发现、100 ms 后 | WAN 约 54 秒就绪 |
| NV 去重后、100 ms | NV 准备约 8.26 → 5.82 秒；WAN 51.39 秒 |
| 50 ms 和 1 秒恢复窗口 | WAN 41.44 秒，LAN 21.60 秒 |
| nr2 连续 60 次 AT | 60 次通过，中位 50.77 ms，最大 102.48 ms |
| nr6 连续 60 次 AT | 60 次通过，中位 50.86 ms，最大 52.71 ms |
| nr7 连续 60 次 AT | 60 次通过，中位 50.86 ms，最大 103.46 ms |
| 实际联网 | 按 netifd 报告的真实接口发送 3 次外网 ping，3 次成功 |
| 用户配置 | 原有 24 项哈希不变 |
| 服务 | 三个独立 AT owner、MM 镜像、USB 监听、网络恢复、短信通知和屏幕均运行 |

以上启动时间是重启样本，从 `/proc/uptime` 的 WAN ifup 事件计时，不是断电冷启动或所有运营商环境的保证；当前没有达到 U30 的二十多秒。180 次 AT 测试也不等于长期负载稳定性认证。

用户已确认取消页面带滑动后不再闪烁。随后尝试淡入被用户指出有重影，因此改成只移动新旧两个相邻页面。最终动画的面板表现需要另行确认，浏览器测试不能替代这一点。
