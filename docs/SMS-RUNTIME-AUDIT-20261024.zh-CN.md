# 网页短信后续检查（2026-10-24）

本轮沿用当前 E5 仓库的共享网页短信实现，检查 RPC 参数、列表刷新及发送交互。
没有回滚前面的省电、语音、短信和摘要缓存修复。

## 已确认并修复

| 问题 | 修复与验证 |
| --- | --- |
| RPC 参数类型不一致；布尔值 `true` 未被 Python 删除分支识别，选择本地+SIM 删除会变成仅本地隐藏 | 公共 RPC 包装统一发送字符串页码、ID、`1/0` 删除模式；适配器同时明确识别布尔值和 `1/0`，拒绝未知模式。旧适配器配合假执行器复现了 SIM 删除调用为 0 次、本地隐藏为 1 次；修复后验证实际调用正确及删除失败时不隐藏 |
| 一次列表错误能长期覆盖正常列表；网络异常会被当成空列表 | 保留最后成功的列表，明确提示错误；首次加载失败后仍可重试。真实网页脚本的失败/恢复用例在修复前失败，修复后通过 |
| 并发刷新乱序返回，旧列表能覆盖新列表 | 读取批次编号隔离过期回复，包括后续分页；假 RPC 逆序完成两个请求，确认保留最新结果 |
| 清空失败仍关闭当前会话，且没有失败提示 | 检查操作结果，失败时保留会话并提示；没有对真实收件箱执行清空 |
| 连续回车可重复提交发送；发送成功会清掉等待期间输入的下一条草稿 | 增加发送中保护，成功时仅清理仍与本次提交一致的草稿，失败保留草稿并解除发送中状态 |
| 中文输入法选词时按回车会触发短信发送 | 忽略输入法组合输入中的回车，覆盖 `isComposing` 与兼容键码路径 |

没有把“参数类型不匹配”直接等同于已实测发生分页丢失；本机实测确认的是修复后
所有短信列表请求的页码均以字符串发送。超过五页的历史加载仍沿用现有界面上限，
本轮没有更改这一产品行为。
