# 网页网络性能设置与驻网反馈（2026-10-26）

两个仓库的「蜂窝 → 设备管理」新增网络性能卡片，沿用当前主题卡片、字段、按钮与提示样式，支持中文、英文、土耳其语。只显示内核当前提供的 CUBIC/BBR，保留「系统默认」，同时展示实际拥塞算法和默认队列。

## 行为与范围

- 默认不改变现有系统策略。用户选择 CUBIC/BBR 后立即写入全局 TCP 默认值，并保存 `/etc/unisoc-network-performance.json`；无后台进程或轮询。
- BBR 配套 `fq` 默认队列。内核使用正常的 sch_fq 模块加载机制。现有接口、连接、SQM/QoS 不替换；新 TCP 连接与新建接口使用新的默认值。
- 系统默认采用本次启动、首次应用前捕获的原设置，恢复时删除此功能的持久化选择。重启重放在普通 sysctl 配置之后、网络接口创建之前进行；无保存配置则直接跳过。
- 非法输入或内核不支持的算法不应用；应用或保存失败会尝试恢复原来的算法与默认队列，并回报恢复是否完整。
- 仅影响设备自身 TCP 发送端行为，不会将热点或 USB 转发的终端连接统一变成 BBR。不写 AT、NV、频率或温控配置。
- 新文件已加入公共 rootfs、插件安装、开机入口、RPC 权限与配置保留路径；MU300 两种内核及 E5 六种 profile 使用同一后端。默认不替用户启用 BBR。

## 驻网读取

确认代码缺陷：MU300 实时信号接口返回 `busy` 时，网页误报“读取失败”；E5 的 fast collector 在通道池忙时正常退出却不生成新文件，RPC 将其统一误报为实时读取失败。

现将 E5 fast collector 的繁忙退出与真实读取失败区分，回放/锁定期间也返回等待，不把旧缓存冒充新 AT 结果。两边页面等待时保留最后有效数据；读取恢复后清除提示，空响应、真实故障和通信错误仍显示失败。没有改变 AT 顺序、所有权、轮询间隔或增加复位。不能据此认定每个用户的读取失败都由繁忙导致。
