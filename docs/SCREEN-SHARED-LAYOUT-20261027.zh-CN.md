# 共用屏幕源码目录整理

## 范围

将历史 `devices/t551m/infoscreen/` 整体移到
[`devices/common/infoscreen/`](../devices/common/infoscreen/README.md)，
E5、T551M、M8、T512N、远航 41S、K1、LYM-10K 使用同一份源码。
不另留旧目录副本、兼容转发模块或符号链接。

- 更新 `devices/t551m/ui.py` 的共用屏幕安装入口。
- 更新原生服务构建器、CI 源码缓存路径、测试输入和当前文档链接。
- `devices/t551m/ui.py` 仍是现有 UI／看板／AT 组装入口，本轮只整理屏幕子目录；
  不顺带改动硬件准备器、板级配置或其他机型适配。
- 设备端路径、服务、RPC、可执行文件名称、权限、启动链接、
  更新兼容标记和用户配置保留规则均不改动。

`t551m-*`、`T551MTransport` 等历史内部名称继续作为兼容接口，
不代表运行第二套屏幕程序。源文件版权、许可和原始插件来源记录随目录一起保留。

## 验证

迁移前保存生成文件和实际 staging 清单，迁移后逐项对比：

- 14 份生成的屏幕源码 SHA256 一致。
- 74 个部署文件／链接的字节、权限、目标完全一致，包含原生 ELF。
- 七款屏幕机型的 staging 和共享运行时检查通过。
- 19 组 Linux 适用测试通过，其中 unittest 共 110 项，另有脚本式检查。
  涵盖原生屏幕服务、临时 D-Bus／HTTP／音频夹具、ASan／UBSan／LSan、
  壁纸、更新兼容、APN、版本读取、充电控制、CI 和源码路径。
- Windows Chromium 六组浏览器测试通过：完整导航、息屏省电、
  三种分辨率／中英文交互、实体键电源菜单、充电插拔唤醒、APN 编辑。
- 两组真实 ARM64 ucode VM 夹具通过：gadget MAC 发现及 USB 设备扫描。
- Node 事件订阅／恢复检查、修改后 Python 语法、旧源码路径残留检查和
  `git diff HEAD --check` 均通过。

依赖完整 E5 离线根的整根重写测试、需要运行中 ubus 的双卡流量服务测试，
本轮未作为无参数脚本运行通过；不计入上述通过数。
相关屏幕生成源码本轮字节不变，流量统计实现没有修改。

测试使用临时文件、现有本地工具链和已有 Docker 镜像，未操作用户设备，
未构建完整固件／安装器或重新打包。原生屏幕辅助程序因构建器路径输入变化，
通过正式任务入口重新验证构建，得到的部署字节与迁移前一致。
测试记录位于 `work/screen-shared-layout-20261027/`，
正式任务日志位于 `out/build-logs/`。
