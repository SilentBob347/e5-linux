### 首次发布遗漏与实机修正

首次实现仅接入 `sprd_panel_enable()`。该平台初始化时把 DSI 标为已启用，冷启动会沿用 bootloader 已点亮的画面，`sprd_dsi_encoder_enable()` 提前返回，跳过面板重新初始化。因此“新模块已加载”不能证明 B9 生效。用户反馈后，核对了内存中的模块 Build ID 与磁盘/本地新模块一致，但实际 B9 仍为 `00`，确认该遗漏。

修正版在冷启动已启用分支增加一次性设置，并保留原有正常初始化设置。使用精确面板匹配、同一面板锁、最大返回包长度设置及 B9 回读；成功后不在重复接管中重写。正常面板复位后仍重新设置。

- 编译任务：`20261026-190227-e5-dither-handoff-70681`，Image、完整模块及 root 模块配套检查通过。
- 部署时动态识别 Linux `boot_b`，备份当前 boot 和模块；保留当前 initramfs 的全部非模块条目、槽位绑定、命令行与诊断区。Android boot 写入前后哈希一致；未写 misc、IMEI 或 NV。
- 为排除手动设置残留，重启前清为 `B9=00` 并回读，正常重启后仅读取，generic/DCS 两种读取均为 `02`；读取像素格式 `77` 后再读 B9，以排除共享读缓存残留。
- 再次清为 `00`，执行一次受控面板 suspend/resume，未手动设置 `02`，读回恢复为 `02`。测试后 ESD 恢复开启、LP 指令模式恢复 `0`，蜂窝 IPv4/IPv6 及热点均正常。
- 证据：`work/e5-dither-live-20261027/`；设备回退备份：`/root/e5-dither-handoff-backup`。本机新版显示模块 Build ID：`9da8bb14f5ed06793c532ec61dbf52e794c05335`。
- 用户撤回了“撤销列表手感优化”的要求；最终继续保留原生滚动、方向识别、按帧拖动等本轮优化。

## 所有屏幕机型共用的交互路径

- 将只观察触摸的监听设为 passive，由 CSS `touch-action` 处理原生纵向滚动和锁屏禁止滚动。保留点击、实体按键、触摸关闭和息屏拦截。
- 纵向滑动一旦成立，后续手指弧线不会误切页；输入框等编辑控件及多指操作不进入页面切换识别，取消事件清理手势。
- 锁屏保留每个输入采样计算释放速度，但合并为每显示帧最多一次样式提交；取消、亮灭屏和解锁会清理待提交帧，避免旧帧覆盖新状态。
- 未显示且不处于退场动画的页面使用 `display:none`，减少后台布局工作；不为每张卡片强制建立合成层。
- HTML 渲染比较上一次输入，而非装饰图标后的序列化 DOM，避免同样数据反复重建列表、丢失焦点和滚动位置。缓存使用 WeakMap，节点移除后可回收。
- 电池图标和进度条仅在值变化时写样式，避免无变化的状态刷新继续触发 DOM 属性变更。
- 实体方向键聚焦使用 `preventScroll`，随后只执行一次既有的平滑滚动。
- 状态请求频率、来电/短信通知、息屏策略和用户设置保持既有行为。
