# 畅行60安装与正式启动回归（2026-10-29）

本轮不再次缩容、不格式化、不重装用户已工作的系统，也未改写原机 NV、IMEI、GPT 或 Android B。用户自行完成了此前释放64 GiB空间后的安装；随后暴露的正式启动问题在本轮处理。

## 找到并修复的问题

1. **面板供应者尚未就绪即永久失败。** 正式启动在约5秒出现 `dsi attach phy failed`，随后显示绑定线程阻塞在 DRM，seatd 打开显示设备也阻塞，实物保留开机 Logo；网页、蜂窝正常。面板驱动在分配及注册嵌入式 `panel0` 之前检查本机 DPHY，未就绪时返回 `EPROBE_DEFER`。避免这条失败路径留下已释放内存支撑的 class 设备。仅畅行60准备器启用，不改其他面板时钟、色深或系统内存。
2. **正式包缺 SPI 控制器自加载。** 旧正式构建只将公共列表中的触摸模块替换为 AXS15205，没有合入本机 `module-order.txt` 中的 `spi-sprd`，也丢失了供应者优先的顺序。现在合并本机和公共请求，再统一解析依赖并去重；本机46项启动列表包含 SPI，显示电源域在显示驱动之前。根系统也写入本机 SPI→AXS 自加载列表。缺少任何必需模块在构建时失败。
3. **Android侧重装的 NV chroot 未挂载设备目录。** ext4工具根中的 `/dev` 不会自动进入另行挂载的旧/新根。所有 NV Python 归档、校验和备份调用现在短时绑定实际 `/dev`，调用结束后解除，失败退出也先解除子挂载。保留 Python 正常随机化，不跳过校验。真实 ARM64 OpenWrt 根、仅测试子进程的 getrandom 禁用、只读 overlay 负例能复现旧缺口；修正后归档、验证、备份及坏 NV 拒绝均通过。
4. **实验性 userdata 镜像原机NV恢复身份检查写死 eMMC。** 改用已加载的公共存储身份函数，按实际父盘读取；eMMC和UFS的匹配/不匹配回归均覆盖。没有扩大恢复授权或改变默认保留工作NV的规则。

此前两处续装修复也重新覆盖：动态 Android B/OpenWrt A 角色记录、只能依据绑定原事务证明接受的旧准备标记；50 MiB 原机 NV 读回使用有精确大小和校验的二进制传输，而非扩大16 MiB元数据读取上限。

## 实机结果及部署边界

最初只替换显示模块并重写 Image 后，根目录仍有旧BTF模块，导致SPI/音频加载错误；这是本轮热部署遗漏，不是新的存储损坏。随后使用已验证的完整模块stager交付235个配套根模块及服务别名，逐一回读通过，并重建含本机SPI的完整启动镜像。

之后正常软件重启成功，AXS固件版本0019、输入设备、浏览器、屏幕电源监视服务和声卡均自动启动；该次新启动未见BTF、Unknown symbol、显示阻塞错误。用户明确确认：**触摸、息屏／亮屏均正常**。原始boot A及旧模块备份保留在本机私有调查目录，不提交到Git。

不能据此保证绝无缺陷：新 detached 在线缩容worker的物理掉电、每种原厂内核的在线缩容、正式卸载归还空间、长期负载仍未逐机硬件验收。当前实机安装是在先前已验证的在线释放空间上完成，不能写成新自动worker全流程已获硬件验证。一次自动亮度API断言与用户同时按键/触摸的操作重叠，没有据此改动已通过的亮屏策略。

构建继续使用固定入口和原有工作区；没有重编未改变的原生安装器，没有新增内核/rootfs副本或迁移构建目录。旧ZIP不会因源码及实机热修自动改变，发布应使用本轮之后重新装配并校验的包。
