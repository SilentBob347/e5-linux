# 畅行60加密 F2FS 在线缩容实测

2026-10-29。用户明确授权在已连接的畅行60保留 Android 数据，缩容留出64 GiB。
本次只做缩容及空闲空间验收，没有安装 OpenWrt、格式化、修改启动链或写 NV。

## 本机证据

- ZTE 7552N / P720S20，Android B，原厂内核 `5.4.254-android12-9-g619997ff2210`。
- 原厂版本 `ZTE/CN_P720S20/P720S20:13/TP1A.220624.014/20240919.212928:user/release-keys`。
- UFS 用户 LUN为sda，4096字节逻辑块；userdata为sda76，起点17846272个512B sector。
- `/data`是F2FS、FBE＋metadata加密，已挂载的解密映射dm-39唯一对应sda76。
- 原始userdata为232071168个512B sector；已用数据约4 GiB，供电在线。
- 本机内核存在`f2fs_resize_fs`。以两个一致超级块中的实际当前块数调用
  `F2FS_IOC_RESIZE_FS`，原大小无操作探测成功；不能把它称为缩容dry-run。

## 执行顺序

1. 经设备端dd、ADB pull和设备/电脑哈希校验，保存主备GPT、misc控制和64 MiB
   metadata分区。记录原文件系统身份、几何、原应用列表、boot A/B哈希及测试文件。
   备份留在电脑私有的`work/changxing60-online-shrink/`，不提交原始镜像、密钥或身份信息。
2. 使用本次编译、逐项校验过的静态ARM64辅助程序。它核对挂载点与块设备身份、
   两份完整F2FS超级块、section对齐、原块数和空间余量。
   程序从`/dev`的内存文件系统执行，通过Android已挂载的`/data`发出内核ioctl，
   不从离线环境获取密钥，也不自行搬移F2FS元数据。
3. 文件系统从29008896个4096B block缩至12231680个block，用时约12.19秒。
   ioctl返回成功后sync，再用直接读取及独立的设备端dd/电脑解析核对两份超级块、
   UUID和测试文件。到这一阶段GPT仍未改变。
4. 仅更改userdata分区的结束LBA，保留起点、GUID、属性和所有其他分区条目。
   先写备份GPT并回读，再写主GPT并回读，两表CRC和完整范围由独立解析器验证。
   使用实际4Kn单位，不在已挂载的Android上强行重读内核分区表。
5. 正常重启Android B。验证新的userdata和dm映射大小、文件系统块数、两份超级块、
   原UUID、测试文件、原248项应用列表及首次设置状态。boot A/B哈希保持原值，
   内核日志没有发现F2FS损坏或UFS I/O错误。

## 经验与边界

- 在线缩容可避开离线无法解密的障碍，但依赖本机原厂内核、已挂载F2FS、root权限、
  健康状态、布局及可迁移空间；不能把一台成功推广为所有机型都通过。
- 必须先成功缩文件系统并核验，再改GPT。两个步骤不是同一个原子事务；需把阶段、
  原表、计划表和实际块数保存在电脑，不能失败后盲目继续缩分区。
- 本机Android Toybox dd不支持`iflag=direct`，会直接报`bad iflag`；辅助程序自身的
  O_DIRECT读取正常。工具不支持参数不等于文件系统或UFS故障。
- 本次保留metadata密钥分区，不搬移userdata起点，不格式化、不停用加密。
- 当前证据覆盖一次真实缩容、一次正常重启及有限数据核验；未逐文件比对全部用户数据，
  未进行掉电故障注入，也未完成正式OpenWrt安装/卸载硬件验收。
- 这项独立高级缩容功能尚未加入安装器UI；现有无空闲区时的加密安装确认流程没有改变。
