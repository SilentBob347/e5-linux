# 畅行60安装器五轮回归

2026-10-29。使用临时文件、磁盘夹具和模拟 ADB/SSH；没有连接或修改实机分区、userdata、NV。

## 修复的实际缺陷

1. 畅行60探测会经 `storage_script → Adapter.push → push_chunks` 上传只读 UFS 身份工具。
   此时尚无安装事务，旧传输代码无条件调用 `context.boundary()`，导致
   `AttributeError: 'NoneType' object has no attribute 'boundary'`。
   现在传输允许没有事务的探测操作，但仍逐块及整文件校验。有事务时仍检查取消和进度；
   `Adapter.action` 仍拒绝探测阶段的正式写入。
2. 畅行60的启动链包含本机需要的 `dtbo/vendor_boot`，原有备份传输允许列表漏掉了这两项。
   已补齐它们的 A/B 分区，仍走 dd、ADB pull 和设备/电脑哈希校验。
   其他机型的备份分区选择没有扩大。

原有探测测试模拟掉了身份工具上传，未覆盖第一个缺陷。新增测试实际执行可移植脚本、
GUI 适配器及分块传输，覆盖 Android A/B、无事务、校验失败，以及探测不能执行 misc 写入。
