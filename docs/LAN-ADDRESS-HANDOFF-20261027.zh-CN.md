# 修改管理地址后仍可访问旧地址

## 确认的代码问题

- E5 旧默认配置将 `192.168.77.1/24` 永久添加到 `network.lan.ipaddr` 列表，作为第二个管理地址。修改主地址不会自动删除列表里的这个地址。
- MU300 的早期 USB 使用 `192.168.77.1`。原 LAN 热插拔脚本只删除与桥地址相同的 USB 地址；保存的新 LAN 地址与早期地址不同，旧地址就会留在桥成员接口上。Linux 的本机地址仍可被访问，即使地址挂在桥成员上。

## 修复范围

E5 新默认配置仅添加 `192.168.9.1/24`。新增一次性 UCI 迁移：仅对已有 E5 初始化标记的静态、多地址 LAN，移除旧默认兼容项 `192.168.77.1/24`，保留其他地址。如果 LAN 唯一地址是 `192.168.77.1/24`，则不删除。迁移失败返回非零，让首次启动机制保留脚本重试；成功后由 OpenWrt 删除迁移脚本，以后不持续限制用户添加地址。

两仓库均处理 `lan/ifup` 和 `lan/ifupdate`。LAN 已有 IPv4 后，清理早期 USB IPv4；MU300 清理已加入 `br-lan` 的 usb0/rndis0，不再要求旧地址等于当前桥地址。桥上配置的额外地址和 IPv6 保持原样。没有添加轮询、USB 重新枚举或网卡关闭操作。

早期启动和救援模式仍可使用临时地址；它不应延续为正常 LAN 的固定兼容地址。正常启动的持久地址由 `/etc/config/network` 决定。

## 验证与限制

- E5：`python3 openwrt/tests/lan-address.py`，6 项测试通过，覆盖旧配置迁移、更换主地址、单地址保留、提交失败及 LAN 事件。
- MU300：`test_upstream_stability.py` 6 项及 `test_usb_management.py` 23 项测试通过，覆盖不同网段、前缀、LAN 未就绪、启动及地址更新事件。
- 在隔离 Linux 网络命名空间中运行两份实际热插拔脚本：4 个场景确认旧地址从内核本机路由表消失，新 LAN、额外桥地址、IPv6 和 USB 链路保持有效。测试脚本在 `work/lan-address-20261027/kernel-handoff.py`。
