# 基带NV设置、更新保留与双向同步

公共路径覆盖 E5、T551M、M8、T512N、远航 41S、K1。入口为 **蜂窝 → 基带NV设置**。
这是程序和页面功能说明；合成数据／loop 测试不能替代真实硬件写回验收。

## 当前实现

| 功能 | 行为 |
| --- | --- |
| 更新与重装 | 保留 `/opt/e5/nv` 工作文件、来源记录及 `/etc/e5-nv` 维护历史 |
| 原机 NV → OpenWrt | 从本机原始九个分区完整导入工作副本；原机不被写入 |
| OpenWrt NV → 原机 | **完整文件写回**固定、运行时 NV；delta/calinv 通过来源或兼容格式验证后也纳入，不再逐条合并或过滤身份项 |
| IMEI | 并排展示当前基带固件槽原机／工作各自的 IMEI1、IMEI2，默认遮挡，点击显示 |
| 备份 | 手动创建原机／工作 NV 快照、下载已有备份；gzip 无损压缩并校验完整字节；删除及旧备份压缩需输入 `yes` |
| 页面 | 三语言、主题适配、先显示页面再独立加载状态／备份；操作进度使用全屏遮罩，顶部显示状态，完成／错误弹窗提示 |

页面不展示其他 NV 内容或原始分区哈希。IMEI 不写入测试输出和报告。
“文件不同”不等于校准损坏：运行时写入、代次、填充和主备配对都可能造成差异。
业务项差异是当前固件槽的只读解析结果，不能代替四个完整固定 NV 文件的比较。

## 手动备份与下载

备份管理区的“手动备份”异步创建原机九文件、工作九文件及来源记录，不执行同步，
不停止蜂窝服务、不发 AT。工作快照沿用现有写入进程的空闲暂停／刷盘机制，异常时也恢复进程。
每个 gzip 快照独立校验，成功后才标记备份完成；失败保留未完成记录，不改变上次同步状态。
备份目录为 `/etc/e5-nv/backups/manual-日期-时间-随机标识/`。

每条备份提供“下载”。服务器在 RAM 中准备 `.tar.gz`，保留 `files/` 下的备份内容、
`download-manifest.json` 的 SHA256／长度及说明文件，归档逐文件回读校验后才提供下载。
内部 `.gz` 是完整 NV 文件的无损快照，使用原始 NV 工具前需要解压。
已有备份不会因下载而重新抓取 NV 或改动。下载通过 LuCI 登录会话和 `cgi-io` 权限校验，
不把 NV 文件放进公开静态目录。

RAM 下载缓存只保留一份校验通过的归档；新的准备失败时保留上一份可下载文件，
临时文件自动清理。持久化备份由用户管理，删除仍需输入 `yes`，未完成恢复事务使用的备份禁止删除。
状态提示位于页面说明下、状态卡片上方；进行中使用全屏进度，结果／错误弹窗显示。

## 工作副本与原始分区

基带访问 `/opt/e5/nv` 的九个 loop-backed 文件：

- 固定 NV：`nr_fixnv1_a`、`nr_fixnv2_a`、`nr_fixnv1_b`、`nr_fixnv2_b`。
- 运行时 NV：`nr_runtimenv1`、`nr_runtimenv2`。
- 其他：`nr_deltanv_a`、`nr_deltanv_b`、`calinv`。

原始分区由共享 `devices/t551m/nv-prepare.py` 设置块设备只读，
`factory-sha256.json` 记录提取来源。保留工作数据时不能把来源直接改成新原机哈希。
原始分区按 sysfs PARTNAME 映射实际 `/dev/mmcblk0pN`，不使用指向工作 loop 的 by-name 别名。

**原机只读保护不等于业务上的 delta/calinv 天生只读。** 2026-10-25 远航 41S
实机的九个工作 loop，包括 delta/calinv，`ro` 均为 0。现有原厂 `cp_diskserver`
证据指向 fixed/runtime 主备管理，`modem_control` 包含 delta 的固件加载路径；
尚不能据此宣称所有型号的 Android 都绝不会写 delta/calinv。不改变现有运行时 loop 权限；
原机写回是否包含它们，由下面的来源／格式检查决定，不能仅凭“loop 可写”断言有效。

## 两个同步方向

两个方向都要求：已知机型、明确槽位、本机分区布局、容量和 NV 头／校验可验证；
生成五分钟有效预览，显示来源、目标及覆盖影响，用户输入精确小写 `yes`。
两边都偏离共同来源时提示冲突；固定／不透明工作数据或原机变化需重新确认，
正常运行时写入不反复使确认失效。

获取与整镜像／差异更新相同的维护锁。停写沿用现有 vendor stop、flush、detach 钩子，
不额外发 SFUN，不改变 AT 所有权、启动回放顺序和用户射频配置。完成后重启生效；
通过 boot ID 清除已重启提示。后台作业有 PID／启动时间识别和真实阶段，避免假进度及永久转圈。

### 原机 → OpenWrt

1. 校验并 gzip 备份原机九文件及旧工作九文件，保存原有来源记录。
2. 从校验过的原机快照构造完整候选工作目录，沿用现有“有效主副本优先”的配对规则。
3. 刷盘、持久化恢复记录，再切换目录。旧目录在切换期间保留，以处理重命名中断。
4. 成功后验证旧目录与独立工作快照相同，再移除其重复内容；保留压缩快照及元数据。
   清理失败只保留重复副本，不把成功导入误报为失败，也不阻碍正常基带启动。

这个方向会覆盖整个工作 NV，**包括工作 NV 中的 IMEI**，原机分区不变。
原机导入仍沿用对不透明来源变化的检查，不能把未经核实的新来源直接标为校验通过；
下面的反向写回则按实际来源和已识别格式逐文件判断。

### OpenWrt → 原机

1. 检查上述全部九个工作文件，各自对应同名原机分区，A/B 不交叉覆盖。
   不假定 Android A／Linux B；当前固件槽用于展示身份及绑定事务，而非限制写回范围。
2. 完整复制每个工作文件，包括其头、代次、IMEI、身份签名、业务项、填充和尾部。
   **不重编码、不改代次、不重新计算或过滤条目**，不把一个槽的文件广播到另一槽。
3. 固定／运行时使用现有 VN 头和校验规则，运行时内部的 VNTS 不当作固定 NV 条目解释。
   运行时可能在确认期间正常变化，使用 vendor stop／flush／detach 后的最终状态作为快照。
   合法的全零未初始化运行时 NV 仍可完整复制，不误用固定 NV 的校验规则拒绝它。
4. delta/calinv 与原机相同时无需写入；与本机来源记录完全一致的原始快照可以恢复。
   新 delta 更改须通过用户工具定义的完整块、版本、长度、终止和零填充检查，且板级选择和
   条目布局与原机一致；仅条目值可以不同，头部标志／版本与原机匹配，不假设固定为 1。
   同机旧 DeltaNV A/B 样本各四个块、101 个记录已只读解析通过。calinv 新更改只在原机与工作都使用已识别的
   VN 校验容器时开放。不能验证的文件在页面和确认框列出，跳过它们但保留其他已验证文件的同步能力。
5. 备份本次包含的原机文件、工作文件和来源记录。工作快照本身就是写入映像，不再额外造候选副本。
6. 持久化绑定机型、CID、槽位、范围、前后哈希的事务记录。固定／运行时先备副本、全量回读，再主副本；单份校准映像按同名分区处理。
   暂时只解除当前目标的块设备只读，成功／失败都恢复。仅跳过已逐字节一致的目标。
7. 确认令牌绑定写回策略及范围。热更新前只授权四个固定 NV 的旧确认必须重新生成，
   不能自动扩大到运行时／校准文件。本次包含的文件全部回读一致才更新各自来源；错误恢复旧快照及旧来源。恢复只依赖旧快照，
   不因新映像快照损坏而阻止使用有效旧快照恢复。
8. 下次启动在任何 NV loop 和 vendor 写入者运行前处理未完成事务。
   完整提交则完成记录，否则恢复旧快照；普通启动无事务时只检查是否存在 journal。

downloadnv、prodnv 等不属于当前九文件工作池，不能凭文件名扩展到其他物理分区。
完整写回会包含源文件中的 IMEI，确认框已明确说明；不能继续承诺“写回时保留目标 IMEI”。
旧版 v1 合并、v2 完整固定 NV 事务只保留恢复读取兼容；新事务为 v3 已验证 NV 范围。
旧合并算法已移除，未验证文件不会被“整体成功”或“全部一致”提示掩盖。

## 备份为何曾达到 327／981 MiB

远航 41S 实际容量：四个固定文件各 50 MiB、两个运行时文件各 55 MiB、
delta 各 1 MiB、calinv 15 MiB，合计 **327 MiB**。这些是完整分区映像，包含填充。
旧更新备份保存一套；旧导入备份同时保存 `source`、`work`、`previous-working` 三套，
所以达到 **981 MiB**，其中后一套重复了 `work`。

新快照采用流式 gzip level 3，不裁剪有效范围，不丢弃尾部。临时文件写完后，
解压逐字节哈希与长度验证通过，才原子发布；失败移除自己未完成的临时文件。
没有对活跃 NV 使用硬链接，防止基带写入同时改变备份。

对电脑上已有的同机旧快照只读测算，327 MiB 压缩为 **4,008,546 字节，约 3.8 MiB**；
这是该份样本的结果，不保证所有机型／运行数据都相同比例。两边各一套约 7.6 MiB。

旧备份不自动删除。页面“压缩备份”会在确认后异步、仅操作选中备份：
验证压缩映像，移除确认重复的旧工作目录和原始快照文件，保留同样的完整内容及记录。
可中断续做，不停止蜂窝，不打开当前工作 NV 或物理 NV，不改上次 NV 同步记录。
恢复事务引用的备份不能压缩／删除。列表同时显示压缩后占用与原始大小。

## 更新路径和保留失败

| 路径 | 处理 |
| --- | --- |
| PC 在 OpenWrt 更新 | 写 root／boot 前下载并校验 NV 归档 |
| TF／内置分区离线更新 | 旧根只读、基带未运行时捕获最终快照，RAM 及恢复后／只读重挂载均校验 |
| userdata `.new` 镜像 | 最终换镜像前再迁移；失败保留旧镜像 |
| Android 重装内置分区／镜像 | 先备份旧根 NV，重装 receipt 与不可变归档绑定，恢复后只读验证 |
| 旧 Debian 目录方式 | 使用同一归档／恢复实现 |
| 差异 OTA | 工作 NV、来源及维护历史位于受保护路径，不被替换／删除 |

工作 NV 无法保留时，先独立校验同机原机 NV，再询问是否放弃工作修改、改用原机。
用户输入 `yes`，选择只绑定本次事务；`-y`、重试或重启不能替代确认。
GUI 自动保存进度，用户不必手动导出记录。设备不符、来源不可验证、实际 IO 失败仍不能跳过。
归档／恢复辅助代码保持独立，可在没有新网页模块的旧根使用。

### 已修复的离线随机源错误

远航 41S 曾在约 4.8 秒启动时报
`_Py_HashRandomization_Init: failed to get random numbers`，继而
`NV preservation failed; old root kept`。电脑端备份已通过，失败发生在 Python 初始化，
尚未校验 NV 或覆盖旧根。原因是只读旧根 chroot 内没有 `/dev`，早期 getrandom 不可用时，
后备 `/dev/urandom` 也不可用。公共调用现在临时 bind `/dev`，成功／异常都释放，
错误写入持久化日志；不固定随机种子、不放宽 NV 校验。
