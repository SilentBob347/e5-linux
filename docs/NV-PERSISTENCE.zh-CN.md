# NV 持久化与显式导入

## 当前交付边界

公共实现覆盖 E5、T551M、M8、T512N、远航 41S 和 K1 的现有隔离 NV 路径。

| 功能 | 当前状态 |
| --- | --- |
| 更新保留工作 NV、来源记录和维护历史 | 已实现；失败时可经确认改用已验证的本机原始 NV |
| 网页“NV 持久化设置” | 已实现，中文、英文、土耳其文 |
| 原机 NV → OpenWrt | 已实现；预览、冲突提示、输入 `yes`、停写、备份、校验、重启生效 |
| OpenWrt NV → 原机 | **禁用**；页面说明未核验校准条目及原机主备写回规则 |
| 设备实测 | **未进行**；下面的测试均使用临时文件或模拟环境 |

不能把“完整 NV 容器的校验和有效”当作“已经识别可写回的校准条目”。
现有代码没有经本机原厂固件核验的校准项 ID、偏移、跨槽位归属、写入次序和失败恢复规则。
因此本次没有新增任何原始 NV 分区写入，也不会先解除原分区只读来尝试写回。

## 已确认的现有行为及依据

依据为仓库当前的 `devices/t551m/nv-prepare.py`、`nv-stop.py`、`nv-verify.py`、
`devices/e5/stage.py::stage_nv()` 及各机型调用公共 staging 的路径。
本次没有提取新的原厂固件版本，也没有把其他型号的 RIL 行为当成本机写回证明。

- 基带访问九个 loop-backed 工作文件，位置为 `/opt/e5/nv/`；原机分区保持只读。
- `factory-sha256.json` 记录提取时的九个原分区哈希，不能在保留旧工作数据时改写成新的来源。
- 固定/运行时 NV 使用现有启动代码的 `0x4e56` 头、长度和校验和规则；全零的未初始化运行时 NV 单独处理。
- 工作副本主备配对沿用现有“校验有效的主副本优先”的规则，仅调整隔离工作文件。
- delta/calinv 的条目格式尚未解析；原机这些文件相对来源记录变化时，禁用导入。
- 旧 `--refresh` 仅刷新原分区哈希改变的文件。因此原分区未变而工作副本已改时，不能用它实现用户要求的“覆盖导入”。

## 网页操作

入口：**蜂窝 → NV 持久化设置**。

页面展示工作副本初始化状态、工作与原机的检查状态、完整文件是否一致、
上次同步方向/时间、备份目录和待重启状态；不显示 NV 内容或原始分区指纹。
一致性是完整文件的 SHA-256 对比；主备配对和正常运行时写入都可能使其不同，
不能仅凭“不一致”认定校准损坏。

原机导入流程：

1. 检查已知机型、明确的基带固件槽位、九个真实块设备、只读状态、容量及 NV 校验。
   不假设 Android 在 A、OpenWrt 在 B。无法识别时不提供同步操作。
2. 生成五分钟有效的确认预览。两边均偏离共同来源时提示冲突；确认后任何相关文件改变都会要求重新确认。
3. 用户输入精确的 `yes`。操作会停止蜂窝服务，网络、电话、短信会暂时不可用，完成后需重启。
4. 获取与整镜像/差异更新共用的锁；已有更新待执行时拒绝导入。停写使用现有服务 stop/quiesce/detach 钩子，不发送额外 SFUN 或改变 AT 所有权。
5. 备份完整工作副本、原机九个文件、来源记录和校验清单。
   位置：`/etc/e5-nv/backups/<时间>-<随机标识>/`；目录仅 root 可进入，备份文件权限为 `0600`。
6. 从已校验的原机备份构造候选工作目录，按现有主备规则配对；刷新文件和目录后切换目录。
   不重新启动基带；RAM 维护标记阻止延迟启动流程在导入中途重新打开 NV loop。
7. 导入失败保留错误和备份；目录切换中断有持久化日志，下一次正常 NV 启动先恢复已有工作数据，不能默默重新提取旧原机数据。
8. 完成后显示需要重启；通过 boot ID 判断是否已经重启，避免永久提示。

## 更新路径

| 路径 | 保留方式 |
| --- | --- |
| PC 安装器在 OpenWrt 下更新 | 写根/boot 前额外下载校验过的 NV 归档；工作 NV 无法保留时先验证原机来源，再询问是否改用 |
| TF / 内置分区离线整镜像更新 | 在原根只读、基带未运行时捕获最终 NV 及维护记录；覆盖前校验 RAM 归档，恢复后及只读重挂载后校验 |
| 旧 userdata `.new` 镜像更新 | 安装时保留快照；initramfs 最终换镜像前再次迁移最新 NV；失败保留旧镜像 |
| Android 重装已有内置分区 | 覆盖前读旧根，备份到 Android `/data/local/tmp/e5-nv-backups/`；恢复后只读验证。未知的不可读旧根先询问是否改用本机原始 NV；需完成本机来源校验与显式确认 |
| Android userdata 镜像重装 | 先读旧镜像并归档 NV，恢复到新 `.part` 后校验；失败不替换旧镜像 |
| 旧 Debian 目录形式安装/更新 | 通过同一实现归档、恢复并校验工作 NV 和历史，不再直接 `cp` 活跃 NV |
| 差异 OTA | 工作 NV 和 `/etc/e5-nv` 均受保护，不属于替换/删除范围 |

电脑备份默认位于 `~/e5-backups/nv-updates/`；图形安装器放在本次安装器的备份目录下。
重装的持久化 receipt 与不可变归档绑定，允许同一事务恢复部分写入的分区，
但不能无提示地覆盖一个未备份、无法读取的旧系统；改用原机 NV 必须另外确认。
成功后的新根另有校验过的 NV 保留副本；历史按文件保留，不把旧归档反复嵌套进新归档。

旧版已经发布的 EXE/启动镜像不会因修改源码自动获得这些行为。
下一次发布必须同时带上新的安装器、启动 ramdisk、公共 NV 准备程序和网页包；无需因此重新编译未改动的内核驱动。

## 保留失败时的选择（2026-10-25）

不要求用户手动保存安装进度，也不要求先导出某个旧记录才允许恢复 NV。
图形安装器自动保存检查结果、确认请求和进度；关闭后从未完成任务继续，会重新显示确认框。

- 正常情况仍默认保留工作 NV，不新增确认步骤。
- 工作 NV、来源记录或保留归档无法校验时，先独立验证**同一设备的原始 NV**，再询问是否改用。
- 弹窗明确提示会放弃 OpenWrt NV 修改，原始 NV 分区不被写入；用户必须输入精确的 `yes`。
- 同意后生成新的来源记录和有效工作副本，支持 TF/内置分区更新、userdata 镜像更新，以及 Android 下的重装。
- 选择只绑定当前安装事务；普通确认、`-y`、重试和重启都不能替代这次确认。
- 已有备份及失败记录保留。无法保存的工作 NV 修改可能丢失，这是确认框明确说明的影响。
- 原机来源不可验证、设备身份不符、并发写入、实际传输或存储故障仍不会被“改用原机”跳过。

原机恢复使用与首次提取相同的九个分区及现有主备配对规则；它不依赖损坏的工作校验值，
也不把“放宽工作副本校验”等同于“接受损坏数据”。旧命令行入口使用终端单独输入 `yes`，
没有终端就不会自动接受。离线启动阶段不凭空替用户确认，只执行已随当前更新保存的恢复选择。
userdata `.new` 的恢复选择额外绑定本机 CID 和机型，并在选定的新根成功准备 NV 后才消费，
避免掉电丢失确认，也避免下一次更新意外沿用。
