# 安装器的机型例外确认

E5 仓库安装器允许用户明确选择使用与检测机型不匹配的已校验安装包。
Android 型号与硬件代号、OpenWrt 当前 profile 不匹配时均提示预期/实际机型，
图形界面需要输入小写 `yes`，命令行也必须明确输入 yes；普通 `-y` 不代替此确认。
该确认不会自动开始写入，仍需检查并确认最终安装计划。

图形界面 `plan` 返回 `confirmation_required=model_mismatch` 和 `model_token`。
token 绑定当前包的协议适配器、profile、内核类型和载荷哈希，以及设备 serial、
CID、型号/板号、系统和本次操作。再次请求需同时提交当前 token 和字面量 yes。
通过后在当前事务保存 `model_override` 和时间，执行、重连及续装重核对该绑定。
两阶段安装允许同一设备正常重启和槽位切换；分区几何与启动角色仍走各自原有校验。
换设备、换包、换操作不会复用旧确认。取消弹窗不会创建事务或执行写入。

更新明确区分旧系统的 source profile 和新镜像的 target profile：
运行时及离线更新先校验旧系统机型、CID、目标容量，写入后校验新镜像目标机型。
旧版仅含 PROFILE 的请求仍按同机型流程处理。电脑端 NV 备份仍标注实际来源机型；
此例外不会修改原机 NV，也不会替代 NV 格式/备份/恢复校验及其单独的恢复确认。

安装包自身的清单与载荷校验、root、A/B 槽位、存储拓扑、分区边界、容量、原安装
记录绑定等检查保留。未知或损坏的安装包不因输入 yes 而被当成有效镜像。
该功能只改 E5 仓库，未更改 MU300 安装器。

回归覆盖：后端精确 yes、过期 token、设备/包/操作改变、事务保存和新上下文复核、
CLI 继续/取消、OpenWrt 更新机型例外；中英文小窗口真实 UI 的输入、取消、重开和
独立最终确认；真实离线更新前置 shell 对旧请求、跨机型来源及错误 CID/容量的检查。
E5 原生 EXE/App、内核和固件发布构建仍暂停；这些改动将在下次重编安装器和组包时生效。
