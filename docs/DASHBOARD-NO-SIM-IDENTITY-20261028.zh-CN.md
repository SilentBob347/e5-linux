# 未插卡看板设备身份修复（2026-10-28）

## 问题和修改

公共看板的未插卡过滤会丢弃整个 `ident`，导致 IMEI、厂商、模组型号、固件版本一起变成空白。这些属于设备身份，不依赖 SIM 或注册成功。

现在保留这四项设备身份及真实射频读回，仅清除已移除卡的 IMSI、ICCID、本机号码与驻网数据。不修改后端 AT 顺序、不增加查询，不改变射频。已同步 MU300 仓库。

## 验证

Chrome 页面回归通过：冷启动未插卡身份读取、清除卡身份且不修改缓存源、跨卡隔离、未知卡状态不冒充未插卡、重新插卡恢复驻网显示。E5 双卡发送离线测试 3 项通过。

群友 F50 的后台发送另在 MU300 复现了 ucode 守护进程拒绝带原子选卡前缀的 CMGS 提交，并已修正；同时修复客户端永久吞 stderr 的问题，保留提交错误和退出状态。所谓继承信号导致发送失败尚未复现；E5 走 ModemManager/E5SMS，没有上述 ucode 校验器，也没有照搬清空环境或重发方案。本轮没有真实收发短信或实机部署。

后续换行回归补齐：公共转发长度检查原来漏算末尾 LF，现精确计入；E5 发送文件采用不转换换行的 UTF-8 读取，保留 CRLF。`forward-sms-newlines.py` 及包含多行用例的 `dual-sms-send.py` 共 5 项通过。MU300 的按行 UCS-2 编码缺陷不在 E5 原生 Python 编码器中，未照搬编码器改动。
